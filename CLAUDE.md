# History by Immersion - Developer Guidelines

## 1. Project Overview & Tech Stack

**Overview**: History-by-Immersion is a web application designed to train pattern-recognition and probabilistic thinking using historical scenarios. Users learn by reasoning through real past events, identifying underlying forces, and estimating outcome probabilities.

**Core Stack**:
- **Framework**: Next.js (App Router)
- **Styling**: Tailwind CSS v4 (Strictly sans-serif/Inter, minimalist design)
- **Language**: TypeScript
- **Database**: Supabase (Postgres + Auth)

> **CRITICAL ARCHITECTURAL CONSTRAINT FOR CLAUDE:**
> This project uses the **Google Gemini API** (via Google AI Studio) for all runtime intelligence, **NOT** the Anthropic API. Claude Code must implement, debug, and maintain Gemini API calls using the appropriate Google AI SDK (e.g., `@google/genai`), consuming `GEMINI_API_KEY` server-side only. Do not attempt to integrate `ANTHROPIC_API_KEY` or Anthropic clients for app features.

---

## 2. Core Implementation Rules

- **Scoring Math**: Brier score calculations (and other pure deterministic metrics) must always be executed in plain TypeScript code. Never delegate strict mathematical operations to the LLM.
- **LLM Outputs**: All Gemini API responses used for application data must enforce strict JSON structures using `response_mime_type: 'application/json'` and matching schemas.
- **Untrusted Input**: Learner rationales passed into scoring routines must be properly sanitized and isolated within prompts to prevent prompt injection attacks.

## 3. Database Schema Reference

The core application relies on a PostgreSQL database hosted on Supabase. Below is the structure of the four core tables:

### `scenarios` (The Library)
```sql
CREATE TABLE scenarios (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  title text NOT NULL,
  mode text NOT NULL,                      -- focused | immersive | fork
  domain_tags text[] NOT NULL DEFAULT '{}',
  forces text[] NOT NULL DEFAULT '{}',     -- from the taxonomy
  difficulty int NOT NULL,                 -- 1-5
  obscurity int NOT NULL,                  -- 1-5
  date text NOT NULL, 
  geography text NOT NULL,
  setup text NOT NULL,                     -- learner-facing, no spoilers
  answer_causal_chain text NOT NULL,
  answer_dominant_forces text NOT NULL,
  answer_common_mistake text NOT NULL,
  answer_nonobvious_force text NOT NULL,
  answer_probability_note text NOT NULL,
  consensus_prob jsonb,                    -- optional: expert/crowd probs at the time
  status text NOT NULL DEFAULT 'live'      -- draft | validated | live
);
```

### `forces` (The Taxonomy)
```sql
CREATE TABLE forces (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  key text UNIQUE NOT NULL,
  name text NOT NULL,
  category text NOT NULL,
  description text NOT NULL
);
```

### `responses` (Every Attempt)
```sql
CREATE TABLE responses (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid,
  scenario_id uuid REFERENCES scenarios(id),
  forces_identified text[] NOT NULL DEFAULT '{}',
  outcome_distribution jsonb NOT NULL,     -- learner's probabilities over outcomes
  rationale text NOT NULL,
  brier_score numeric,
  force_recall numeric,                    -- fraction of dominant forces they caught
  reasoning_score numeric,                 -- Gemini's 1-5 judgment of rationale quality
  missed_nonobvious_force boolean,
  ai_feedback text,                        -- Qualitative feedback generated by Gemini
  created_at timestamptz DEFAULT now()
);
```

### `user_profile` (The Personalization Layer)
```sql
CREATE TABLE user_profile (
  user_id uuid PRIMARY KEY,
  calibration_curve jsonb,                 -- over/underconfidence by probability bucket
  force_blindspots jsonb,                  -- forces they rarely invoke or consistently miss
  domain_strength jsonb,                   -- accuracy by domain
  recurring_biases text[] DEFAULT '{}',    -- e.g. "underweights regulatory risk"
  session_notes text[] DEFAULT '{}',       -- rolling 3-sentence summaries
  updated_at timestamptz DEFAULT now()
);
```

## 4. Build & Development Commands

Use the following standard commands to operate this repository:

- **Start Local Dev Server**: `npm run dev`
- **Build Production Bundle**: `npm run build`
- **Start Production Server**: `npm run start`
- **Run Linter**: `npm run lint`

*(If using Supabase CLI locally for testing/migrations, the standard `npx supabase start` and `npx supabase db push` commands apply).*
